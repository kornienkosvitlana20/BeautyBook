# BeautyBook — система пошуку та онлайн-запису до beauty-фахівців

Навчальний кросплатформений вебпроєкт на C# / ASP.NET Core MVC / SQLite. Інтерфейс відкривається у браузері на Windows, Linux, macOS, Android та iOS. Сервер можна запускати на Windows, Linux або macOS за наявності .NET 8 SDK.

## Можливості поточної версії
- Реєстрація та вхід користувача через ASP.NET Core Identity.
- Перегляд каталогу активних майстрів, пошук за ім'ям/спеціальністю та фільтр за містом.
- Профіль майстра зі списком послуг, цінами та тривалістю.
- Створення онлайн-запису авторизованим клієнтом.
- Перевірка майбутньої дати, кроку часу 15 хвилин, відповідності послуги майстру та перетину записів.
- Перегляд і скасування власних майбутніх записів.
- SQLite, зовнішні ключі, індекси, валідація моделей, анти-forgery токени та параметризовані запити EF Core.
- xUnit-тести доменних правил і GitHub Actions CI.

## Вимоги
- .NET 8 SDK
- Git

Перевірити встановлення: `dotnet --version`.

## Запуск з нуля
```bash
git clone <URL_ВАШОГО_GITHUB_РЕПОЗИТОРІЮ>
cd BeautyBook
dotnet restore BeautyBook.sln
dotnet run --project BeautyBook.csproj
```
Відкрийте адресу, яку надрукує команда `dotnet run` (зазвичай `https://localhost:7xxx` або `http://localhost:5xxx`). База `beautybook.db` створиться автоматично під час першого запуску, а також будуть додані демонстраційні майстри й послуги.

Для зупинки натисніть `Ctrl+C`. Щоб почати з чистою локальною БД, зупиніть застосунок і видаліть `beautybook.db`.

## Тестування
```bash
dotnet test tests/BeautyBook.Tests/BeautyBook.Tests.csproj --collect:"XPlat Code Coverage"
```
Тести перевіряють перетин часових інтервалів, суміжні записи, запис у минулому, допустимий крок 15 хвилин і некоректний час. CI запускає restore/build/test на GitHub Actions після push та pull request.

## Статичний аналіз
```bash
dotnet format BeautyBook.csproj --verify-no-changes
dotnet build BeautyBook.csproj -warnaserror
```
Збережіть фактичний вивід команд у `docs/evidence/` під час підготовки до захисту. Не зазначайте вигадане покриття або результати аналізатора.

## Архітектура
- `Controllers/` — HTTP-запити та сценарії користувача.
- `Models/` — сутності користувача, майстра, послуги та запису.
- `Data/` — EF Core контекст і ініціалізація SQLite.
- `ViewModels/` — моделі введення з DataAnnotations.
- `Views/` — Razor-сторінки.
- `DomainRules.cs` — незалежні від UI правила часу та перетину інтервалів.
- `tests/` — автоматизовані тести.
- `.github/workflows/ci.yml` — безперервна інтеграція.

## Робота з GitHub
Працюйте через окремі гілки, не комітьте напряму в `main`:
```bash
git checkout -b feature/master-search
git add .
git commit -m "Add master search and filters"
git push -u origin feature/master-search
```
Створіть Pull Request у GitHub. Інша учасниця має перевірити PR, залишити змістовний коментар (наприклад, про безпеку, граничний випадок чи дублювання запису), автор виправляє його, після чого reviewer перевіряє виправлення й approve/merge. Для кожної завершеної задачі має бути Issue.

## Важливо для навчального захисту
Демо-дані не є реальними майстрами. Поточна версія — робочий MVP: у ній є каталог, автентифікація та клієнтський запис. Адмін-панель, окремий кабінет майстра для керування графіком і production-розгортання потребують окремого розширення. Не видавайте ці функції за вже реалізовані. Перед демонстрацією перевірте застосунок на кожній ОС фактично.
