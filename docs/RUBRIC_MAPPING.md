# Відповідність критеріям із PDF викладача

| Критерій | Що підготувати / де шукати | Поточний стан |
|---|---|---|
| A1 дедлайни | Два чекпоінти, timestamps Issues/PR та артефакти | Заповнювати команді |
| A2 Git/logbook | ≥1 змістовний коміт/тиждень, коміти до Issue, README, ≥5 записів проблема→рішення, гілки | Структура і README є; історію створити реально |
| A3 feedback | Зауваження чекпоінтів оформити Issue і закрити до наступного етапу | Заповнювати за фактом |
| B1 внесок | Issue → branch → PR → commits → review → merge, код і тести | Розподіл у TEAM_SPLIT.md; Git-артефакти створити |
| B2 зобов'язання | Таблиця задач, строків, статусу та попередження про ризик | Шаблон у TEAM_SPLIT.md |
| B3 review | Для кожного review: проблема, реакція автора, перевірка виправлення | Виконати в GitHub; косметичні коментарі не рахуються |
| C0 ОС | Демонстрація роботи на двох або більше ОС | Не перевірено в цьому середовищі |

| C2 крайні випадки | П'ять випадків у TEST_PLAN.md | Продумані; виконання зафіксувати |

| C5 дані/безпека | Схема, PK/FK, індекси, параметризовані запити, транзакції | EF Core, PK/FK, індекси, валідація; транзакційність бронювання потребує посилення |
| D1 зона відповідальності | Пояснення власних файлів, складності й результату | Розподіл у TEAM_SPLIT.md |
| E1 питання | Кожна готує відповіді на питання викладача | Підготуватися окремо |
| E2 зміни на льоту | Кожна має вміти внести 1–2 малі зміни | Вправи наведені нижче |
| E3 README | Запуск з нуля за README | README доданий; перевірити на чистому середовищі |

## C5 — схема даних
- `AspNetUsers` (Identity) — користувачі.
- `Masters` — фахівці.
- `BeautyServices` — послуги майстра, FK `MasterId`.
- `Bookings` — запис клієнта, FK на користувача, майстра й послугу.
- Індекси: `Masters(City, Specialty)`, `Bookings(MasterId, StartAt, EndAt)`.
- EF Core формує параметризовані SQL-запити; не конкатенуйте SQL з введенням користувача.
- PK створюються EF Core. Унікальність email забезпечує Identity.
- Запис бронювання треба вдосконалити транзакційною/атомарною перевіркою для конкурентних запитів.
